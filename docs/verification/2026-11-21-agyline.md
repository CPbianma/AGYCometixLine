## 真实 AGY 与反例

本轮最终使用 Antigravity CLI **1.5.14**。临时会话在 132 列终端中收到原生数据、5 个动态额度 bucket，并在终端流观察到 `% left`。不带临时覆盖的已有安装同样观察到额度文本；该模式不捕获 payload，不能据此独立断言 bucket 数量。两次检查均未发现 `invalid status line input`，启动前后持久 `settings.json` 摘要相同，没有发送模型提示。

为检查验收脚本本身，另用隔离的 `AGYLINE_HOME` 配置只显示模型。宿主仍提供 5 个 bucket，但终端没有额度文本。**旧脚本错误返回 0，修正后同一反例返回 1**。现在临时覆盖模式要求同时取得原生额度和终端额度文本；持久模式仍只检查输出。这是针对显示百分比剩余额度布局的检查，不是对自定义隐藏额度、仅有数额或无额度账户的产品故障判定。

## 配置器操作与复验

独立 Windows 伪终端运行正式版 `--config`，从空工具目录进入向导，选择 ASCII 和 `minimal`，跳过连接并退出。检查保存的 TOML 后，另启一个 release 进程读取该配置：样例确实变成一行，含模型和剩余额度；隔离宿主的设置文件未被创建。

在 Windows、已构建 release、已装 `pywinpty` 的 Python 3.11+ 环境运行：

```powershell
python -m unittest discover -s scripts -p test_verification.py -v
python scripts/test_tui_terminal.py -v
```

本机分别通过 6 项验证脚本回归和 1 项 TUI 交互测试。真实宿主的两种模式可按[上次记录的复验命令](2026-11-20-agyline.md#reproduction)执行；已有安装不需要再运行 `--apply`。如果 `--output` 已存在，脚本会打印本次新建的子目录，不覆盖旧摘要或删除先前捕获。

- 本机没有运行 Linux/macOS，也未推送或触发远程 CI。Windows TUI 测试已加入 CI 定义，但这不代表远程运行通过。
- 保持仅本地／源码分发；上游许可证材料的缺口和公开分发条件不因本次功能验收而改变。
